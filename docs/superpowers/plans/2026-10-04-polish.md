### Task 1 (backend)
1. **Hidden subjects' tasks are hidden too:** tasks whose subject is hidden are excluded from `GET /api/tasks` (board), the weekend review lists (overdue / due this week) and subject/event open-task counts' totals shown elsewhere (`subject_summaries.open_tasks` stays per subject — hidden subjects show 0 sessions already; keep their own count). Add `include_hidden=true` query param on `GET /api/tasks` for completeness. Tests.
2. **Faster first Google push:** in `app/gcal/push.py`, run Google calls for consecutive `insert`/`update` ops in parallel (a `ThreadPoolExecutor(max_workers=4)` over a batch of up to 8 ops; each worker uses its own `GoogleSession`/client built by the factory — never share an httpx client across threads), then apply the DB updates for the batch sequentially in the main thread and commit; keep deletes/removes sequential; keep the lease, the time budget check before each batch, rate-limit stop, auth handling and calendar-missing handling semantics. Tests with FakeCalendar (thread-safe) proving the same final state as sequential, rate limit inside a batch stops the run with correct `remaining`, and a failure in one op of a batch doesn't lose the others.
3. **Hardening:** `require_cron_or_user` compares `x_cron_secret.encode()` with `settings.cron_secret.encode()` via `hmac.compare_digest` (non-ASCII header must not 500) — test; `.github/workflows/sync.yml` curl gets `--max-time 70` and the job `timeout-minutes: 3`; `backend/pyproject.toml` `[tool.pytest.ini_options] filterwarnings` ignores the Starlette TestClient httpx deprecation warning so test output is clean.
4. **Zeus group change:** when `PATCH /api/semesters/{id}` changes `zeus_group_id` to a different non-null value, record `semester.group_changed_at = now` (new nullable column, migration `0008`, RLS unaffected); `apply_feed` skips the "different group" guard (but keeps the keep-missing guard semantics replaced by normal cancellation) for the first sync after a group change, then clears the marker. Test: change group → next sync replaces the old group's upcoming classes (old ones cancelled), marker cleared.
