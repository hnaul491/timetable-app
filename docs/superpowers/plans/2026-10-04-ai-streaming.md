# AI streaming replies — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** The Assistant's reply appears progressively (token by token) with live status steps while tools run, instead of a static "Replying…" until the full answer arrives. User request 2026-10-04.

**Architecture:** New `POST /api/chat/stream` returning Server-Sent Events (`text/event-stream`) from a FastAPI `StreamingResponse` (Vercel Python functions stream ASGI responses). The backend uses Gemini `:streamGenerateContent?alt=sse`, forwards text deltas immediately, runs tool rounds between model rounds (same ≤ 5 calls, same 40 s budget, same propose-only tools), and persists the user + assistant messages at the end exactly like `POST /api/chat`. The frontend reads the stream with `fetch` + `ReadableStream` (EventSource can't POST), renders deltas live, shows status chips, and falls back to the existing non-streaming endpoint if the stream fails before any data.

## Global Constraints
- No new dependencies. Existing `POST /api/chat` stays (fallback + tests).
- Same safety rules: no write tools, writes only via confirm, API key never in responses/logs/errors, model text rendered as text.
- Event format (one JSON object per `data:` line, `event:` names): `status {"step": "events"|"tasks"|"notes"|"subjects"|"free_slots"|"proposal"}`, `delta {"text": "…"}`, `done {"message": ChatMessageOut}` (same shape as `POST /api/chat`'s `message`, incl. `actions`), `error {"message": "<safe text>"}`; a final `done` or `error` always ends the stream. Headers: `Cache-Control: no-cache`, `X-Accel-Buffering: no`.

### Task 1 (backend)
- `LLMProvider.stream(system, turns, tools, timeout=None) -> Iterator[StreamPart]` where `StreamPart` is `TextDelta(text)` or `CallPart(FunctionCall)` (calls keep `thought_signature`); `GeminiProvider.stream` POSTs `…:streamGenerateContent?alt=sse` (header key, same body as generate incl. generationConfig/tools), iterates SSE lines (`data: {json}`), yields text parts as deltas and functionCall parts as calls; errors map exactly like `generate` (429 → AIRateLimited, other → AIUnavailable with `_log_google_error`), raised before or during iteration. `FakeProvider` gains `stream_script`.
- `assistant.stream_chat(session, llm, user_text, context, locale, now) -> Iterator[event dicts]`: same system prompt/history/tool loop/deadline as `run_chat`; per model round, forward `delta`s; when the round ends with calls, emit one `status` per call (map tool name → step), execute tools, continue; on finish persist both messages + action ids (reuse the same persistence helper as `run_chat` — refactor so both share it) and emit `done`; any AI error → `error` with the safe text and NO persistence of a partial assistant message (the user message is still stored so history stays consistent? — store the user message and an assistant message containing the error text marked as such? Keep it simple: store nothing on error).
- Router `POST /api/chat/stream` (same body as `/api/chat`, `require_user`, 503 JSON when AI is off — before streaming starts) → `StreamingResponse(generator, media_type="text/event-stream")`; the DB session must stay open while the generator runs (create/close it inside the generator or keep the dependency alive — verify with FastAPI's yield-dependency semantics and test).
- Tests: Gemini stream parsing (MockTransport SSE body with two text chunks and a functionCall chunk; error status); stream_chat event order for text-only, tool round then text, proposal → action in done, budget exhausted, AI error → error event and nothing persisted; HTTP test reading the SSE body.

### Task 2 (frontend)
- `lib/chatStream.ts`: `streamChat(body, handlers: { onStatus(step), onDelta(text), onDone(message), onError(message) }, signal) -> Promise<void>` using `fetch('/api/chat/stream', { method: 'POST', headers: authHeaders + JSON, body, signal })`, parsing SSE frames across chunk boundaries; non-OK response before streaming → throw ApiError (translated) so the page can fall back.
- AssistantPage: on send, add the user message, then an in-progress assistant bubble that grows with deltas (rendered as text, with a blinking caret), status chips above it ("Checking your timetable…", "Looking at your tasks…", "Reading your notes…", "Looking for free time…", "Preparing a suggestion…" — en/vi), a **Stop** button (AbortController; keeps the partial text visible marked "stopped", and invalidates `["chat"]` to resync), on `done` replace the bubble with the final message (with action cards); on stream failure before any delta → fall back to the existing `POST /api/chat` path; errors as toasts (translated). Respect reduced motion for the caret.
- Tests (mock `fetch` with a ReadableStream of SSE text split across chunks): live delta rendering, status chips, done replaces bubble with cards, Stop aborts, fallback to POST on 404/500 before data, error event shows a toast.
